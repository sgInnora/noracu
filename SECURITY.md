# Security Policy

noracu gives an MCP client control over your **real machine** — mouse,
keyboard, clipboard, browser, and (via iPhone Mirroring) your phone.
Treat every tool call as privileged.

## What noracu hands to your model, and what it can reach

noracu acts inside your real, logged-in session. It does not sandbox what it
touches, and it does not sanitize, filter or rate what it observes: the MCP
client and its model decide what to do with every result. The threat table
below has the per-tool detail.

| Asset | How noracu touches it | Who receives it | What noracu does and does not do |
|---|---|---|---|
| Text returned to the model — AX values and titles, ARIA snapshots, page text, iPhone OCR, screenshots | Every observation tool returns it as read | The MCP client and its model provider | Not sanitized or filtered. A web page, document, message or notification can carry instructions aimed at the model; treat every result as untrusted data (threat 11) |
| Clipboard | `mac_paste`, `phone_type` and `phone_open` put the text on the Mac clipboard and paste it | Apps on the Mac; the iPhone, which fetches the paste from the Mac clipboard through iPhone Mirroring | `mac_paste` sets every item aside and puts it back once the paste shows, but not while the app does not answer — then the pasted text stays on the clipboard (threat 10). The iPhone fetches a paste late, from whatever the Mac clipboard holds at that moment, so `phone_type` puts the clipboard back only on screen evidence and otherwise leaves the typed text on it; `phone_open` never puts it back (threat 18). Items a password manager marks concealed are never copied |
| macOS privacy-consent prompts and administrator authorization dialogs | A synthesized click or keystroke can be aimed at them like any other window | — | noracu does not recognize these dialogs or refuse input to them, and whether macOS accepts a synthesized click on each of them has not been measured. Keep a person present for any run that may raise one |
| Secrets an app displays (Keychain items an app shows, passwords shown in clear, one-time codes) | AX reads, OCR and screenshots read what is on screen | The model provider | Reading is not blocked. `mac_set_value` never echoes a value in a secure text field, and concealed clipboard items are never returned (threat 16) |
| Browser cookies | The browser layer keeps one persistent Playwright profile at `~/.noracu/browser-profile` | Every site the browser opens; page text goes to the model | Not isolated between runs; clear the profile between untrusted runs |
| iPhone Mirroring session | Phone tools see and act through the iPhone Mirroring window | The model sees the phone screen, including notifications, messages and codes | Biometric authentication requests fail during iPhone Mirroring by default (Apple TN3210), but a Mac set to authenticate automatically gives anyone at the unlocked Mac the phone (threats 6, 12). Input reaches iOS as indirect pointer events, not touches (TN3210), so a touch-only system gesture such as swiping in from the left edge to go back does nothing through the mirror — that is the mirror's behaviour, not a noracu fault. Apps on the phone see each capture of the mirror window as a screenshot (threat 21) |

Boundaries:

- macOS grants Accessibility and Screen Recording to the host app that starts
  noracu (Claude Desktop, Cursor, a terminal), not to noracu. Whether macOS
  attributes events from helper binaries such as `cliclick` and `python3`
  separately is unverified.
- noracu does not constrain the host's own shell or file tools. Blocking an
  app inside noracu would not stop a host that can run commands, so noracu
  keeps no such list.
- Tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`,
  `openWorldHint`) are hints for the client and restrict nothing.
  `NORACU_READ_ONLY=1`, `NORACU_DISABLE_EVAL=1` and the opt-in `NORACU_ENABLE_EVAL`
  and `NORACU_ALLOW_*` variables are what the server enforces.
- No telemetry. noracu itself makes no internet connection at run time except
  the one-time Playwright Chromium download, which
  `NORACU_DISABLE_AUTO_INSTALL=1` turns off. The browser layer's Chromium is a
  browser: the pages it is told to open, and the scripts they run (and
  `browser_evaluate`'s, when eval is on), connect wherever they ask, as in any
  browser. The XCUITest backend (opt-in) adds one more channel off the Mac: the
  CoreDevice tunnel between the Mac and a paired iPhone. The runner on the
  iPhone listens only on the tunnel's own address — a unique-local address
  (fc00::/7), or `::1` when CoreDevice reports the tunnel that way; a
  simulator's runner listens on `127.0.0.1` on the Mac itself.

## Defaults and switches

noracu runs with the privileges of your MCP client. It clicks, types, pastes, and drives a real browser on this machine — there is no sandbox and no remote approval prompt. Set these on the server entry, then quit the host completely and reopen it:

```json
"env": { "NORACU_READ_ONLY": "1", "NORACU_DISABLE_EVAL": "1" }
```

- **Tool annotations are hints, not permissions.** Every tool reports the four MCP tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`), set by what the tool does — see [docs/tools.md](docs/tools.md). A client may use them to decide what to confirm with you; they restrict nothing, and a client that asks for the 2024-11-05 protocol revision (which has no annotations) may ignore them. They also do not mirror `NORACU_READ_ONLY=1`: `mac_clipboard_read` is read-only by behaviour yet refused there, and `browser_navigate` is allowed there yet not read-only.
- **`NORACU_READ_ONLY=1`** is the safe first-run mode. It refuses every tool not on a 21-name allowlist (the observe tools plus standalone `browser_launch`/`browser_navigate`/`browser_close`; `browser_launch` with `cdp_port` is refused even when `NORACU_ALLOW_CDP` is set); every click, type, paste, and eval tool is denied, and so are `mac_clipboard_read`, `mac_notifications`, and `mac_wait` with `condition: "notification"`, while `mac_ax_state` and `mac_find` do not toggle `web_accessibility` on apps. `browser_navigate` is on the allowlist, so it can still load a URL.
- **`browser_evaluate` is off by default.** It runs any script in the page, so it returns `eval_disabled` unless the server was started with `NORACU_ENABLE_EVAL=1`; `NORACU_DISABLE_EVAL=1` keeps it off even then. It stays listed in `tools/list`. Snapshot, click, and type still work.
- **`file://` is refused** unless `NORACU_ALLOW_FILE_URL=1`, so a browser agent can't read `~/Documents` by navigating to it. (The browser itself may follow a redirect during navigation, but every subsequent tool call and in-flight read/snapshot re-checks the active page's URL and refuses non-passing URLs — see SECURITY.md.)
- **Focus guard:** pass `app` to `mac_paste` / `mac_key` (and `mac_type` when it sends keystrokes) and input is refused unless that app is frontmost. Omit `app` and the guard is off. `mac_type`'s default accessibility path writes into a named element or the app's focused element and sends no keystrokes at all; it falls back to keystrokes only into a text view accessibility cannot write (a terminal), never when the focus is a button, list or sheet, and into an app that reports no focused element only when `app` names it (otherwise `no_focus`, nothing sent).
- **Stale-element protection:** an `element_index` is not a coordinate. It expires after 30 s, and on the Mac it is never reused by a later snapshot. A Mac element is re-identified inside the very window or open menu it was seen in (by window ID), at the same place in that window, under the same labelled ancestors and in the same table row; an element without a label or identifier must still be exactly where it was. An element read with `surface: "app"` is bound to its window's ID too, and a window without an ID (other than Finder's desktop) is refused with `policy_denied`, so a window closed and reopened with the same content never inherits old indexes. A browser click re-checks tag/name/href/position. Otherwise `element_no_longer_valid`.
- **Hit test before physical clicks:** a Mac click or drag that has to use the pointer is sent only when the element at that point is the target — or, when accessibility cannot tell, when the topmost on-screen window there is that same window (by window ID, not covered by another window of the same app); otherwise `occluded`, with what is on top. Right before the click is sent, the window on top at the point is checked again; afterwards the result is `delivered_verified` only if the element is still there, changed, and its own window is still on top at the point. A click at raw x,y goes out only when the topmost on-screen window at that point belongs to `app` (default: the frontmost app; the menu bar counts as the frontmost app's); `force: true` skips that check. Keystrokes typed after such a click go out only if the element's app is then frontmost.
- **Background windows:** semantic Mac actions also work on windows you are not looking at. That is the point (no stolen focus), but it means an agent can act where you do not see it — watch the results' `delivery` and keep high-stakes apps closed.
- **Background clicks and keys (bgpost):** under `mechanism: "auto"`, a physical click on a native app, and a named key for a native frontmost app, are posted straight to the app's process — the pointer does not move, and you may not see it happen. Web-engine apps (Chromium/Electron) and `mechanism: "physical"` use the real pointer; the result's `route` says which. A posted click is never re-sent another way: no visible change is reported as `delivered_unverified`, a timeout as `delivery=unknown`. `NORACU_NO_BGPOST=1` turns this off.
- **Stop, deny, approve:** while the file named by `NORACU_STOP_FILE` exists, every input tool returns `user_stopped` and sends nothing — Mac (`mac_*`), iPhone (`phone_*`, `ios_*`) and browser input (`browser_navigate`, `browser_click`, `browser_type`, `browser_fill`, `browser_press_key`, `browser_scroll`, `browser_evaluate`, `browser_tabs` new/close); observation tools are not stopped (`touch` it to stop, delete it to resume). `NORACU_DENY_APPS` lists apps that never get input — by default the common terminal apps (Terminal, iTerm2, WezTerm, Ghostty, Warp, Alacritty, kitty, Hyper, Tabby, Rio, Wave) and the IDEs with a built-in terminal (VS Code, Cursor, Windsurf, Zed, JetBrains IDEs, Android Studio — their preview and nightly editions too; the name `Code` and `com.jetbrains.*` also catch any app named exactly Code and JetBrains Toolbox), so an agent cannot type into those shells (other apps that host a shell are not on it); a list of your own adds to it, and a list starting with `none` drops it. `NORACU_APPROVAL_FILE` (opt-in) names a `0600` JSON file `{ "allow": [...], "ask": [...], "deny": [...] }` of bundle-id or app-name patterns: an app under `ask` or not listed gets `approval_required`, and noracu never writes the file; once the variable is set, a missing or broken file refuses all Mac and iPhone input (the browser layer is not judged by app rules; the stop file stops it). An app whose bundle id cannot be read gets nothing while either rule is in force. Each check judges the app that receives the input — the element's app, the named app, or the app on top at an x,y point — and an app that cannot be identified gets nothing. These files stop the model, not other software running as you: see SECURITY.md.
- **Guarded keys, menus and quits:** `mac_key` refuses quit / log-out / lock / force-quit / delete-immediately / empty-Trash chords unless `force: true`; `mac_menu_command` applies the same chord list to menu shortcuts and refuses Apple-menu items unless `force: true`. Neither `mac_app` nor `mac_menu_command` ever quits Finder, the Dock, loginwindow, other session processes or the MCP host itself; `force: true` is needed on `mac_app` to force-quit.
- **Your own Chrome is opt-in:** `browser_launch` with `chrome: true` needs `NORACU_ALLOW_CHROME=1` and Chrome's own remote-debugging switch (`chrome://inspect/#remote-debugging`); Chrome asks you to allow each connection and shows a banner while it is open. noracu then opens a window of its own in your Chrome and lists, reads and acts only on the tabs it opened there (and tabs those open); noracu never lists, reads or acts on your other tabs unless you also set `NORACU_CHROME_TABS=all` (then your tabs on http(s) pages — never `file://` or browser pages, whatever `NORACU_ALLOW_FILE_URL` says — are listed and can be selected, read and acted on, but never closed or sent to a non-http(s) address; one becomes the active page only when selected and stops being it when it leaves http(s)); in noracu's own tabs the address rules (http(s) only; `file://` needs `NORACU_ALLOW_FILE_URL=1`) apply. Those tabs carry your sign-ins, so an agent working there acts as you on those sites; `browser_evaluate` never runs there. `browser_close` closes noracu's tabs and disconnects; noracu never quits Chrome. Refused under `NORACU_READ_ONLY=1`.
- **DevTools ports are opt-in:** `mac_app` / `browser_launch` with `cdp_port` need `NORACU_ALLOW_CDP=1` (`NORACU_ALLOW_CDP=any` to attach to a port `noracu` did not open itself; always refused under `NORACU_READ_ONLY=1`), bind to 127.0.0.1 only, canonicalize `.app` paths and refuse an app that is already running or that the app rules (deny list, approval file) rule out, and give Chrome-family browsers a separate `0700` profile under `~/.noracu/cdp-profiles`. While the port is open, any local process can control that app (127.0.0.1 has no per-user isolation).
- **Clipboard, password fields and notifications are private:** `mac_paste` puts the user's clipboard back (every item and type) and never copies an item a password manager marked concealed — it clears the clipboard after the paste instead; `mac_clipboard_read` never returns a concealed item; `mac_set_value` on a secure password field (`AXSecureTextField`) never echoes the value; `mac_notifications` returns notification text verbatim. `mac_clipboard_read`, `mac_notifications`, and `mac_wait` on notifications are outside read-only mode.
- **iPhone screen is model input:** `phone_screenshot` / `phone_ocr` / `phone_find` return whatever the phone shows — notifications, messages, one-time codes. Use a Focus and a neutral app, and start with `NORACU_READ_ONLY=1` (phone observation allowed, phone input refused). Phone input is also refused when the mirror is not live (`mirror_not_live`) or its state cannot be read (`mirror_state_unknown`).
- **Injection-safe JXA and stdin text:** the accessibility engine (`src/mac-ax.js`) is a static script that takes its whole request as JSON on stdin — parameters are data, never script source — and `mac_type` (default path), `mac_set_value`, `mac_paste`, and `phone_type` / `phone_find` / `phone_open` pass text on stdin so it does not appear in a process list (`imctl type` never echoes it either). Regression-tested.

**What it refuses by default** — a refused input sends nothing, and its error says so (`delivery=not_delivered, retry=safe`):

| Refused by default | Answer | To change it |
|---|---|---|
| Input into terminals and IDEs with a built-in terminal | `input_denied` | `NORACU_DENY_APPS` (a list starting with `none` drops the default), or one app at a time: an approval file's `allow` entry that names it exactly |
| `browser_evaluate` (any script in the page) | `eval_disabled` | `NORACU_ENABLE_EVAL=1` |
| `file://` pages in the browser | refused at the URL | `NORACU_ALLOW_FILE_URL=1` |
| DevTools ports (`cdp_port`) | refused | `NORACU_ALLOW_CDP=1` |
| Working in your own Chrome (`browser_launch` with `chrome: true`) | `policy_denied` | `NORACU_ALLOW_CHROME=1`, and Chrome's switch at `chrome://inspect/#remote-debugging` |
| The iPhone tools | not listed; a call answers `unknown tool … the iphone layer is off` | `NORACU_LAYERS=mac,browser,iphone` |
| Mac input and iPhone Mirroring input while you use the keyboard or mouse | `user_active` | `NORACU_USER_IDLE_S=0` |
| Quit, log-out, lock, force-quit, delete-immediately and empty-Trash chords; Apple-menu items | refused | `force: true` |
| Every input while the stop file exists — once you name one with `NORACU_STOP_FILE` | `user_stopped` | delete the file |

These switches do not make observed content trustworthy. Screenshot text, accessibility names, and page content are untrusted input to your model — do not let them override the task. Full threat model and per-threat status: [SECURITY.md](SECURITY.md).

## Threat model

| # | Threat | Vector | Status | Mitigation / notes |
|---|---|---|---|---|
| 1 | **Prompt injection → arbitrary code execution** | Observed content (web page text, AX tree titles, OCR output) contains instructions that trick the agent into calling tools with malicious arguments | **Mitigated** | The Mac accessibility engine `src/mac-ax.js` is a static script that takes its whole request as JSON on stdin — parameters are data, never script source (regression-tested in `test/e2e.mjs`); the remaining inline JXA (scroll wheel) takes clamped numbers through argv |
| 2 | **Arbitrary local control** | `mac_click` / `mac_type` / `mac_paste` can operate password managers, banking pages, terminals | **Inherent** | Use client-side confirmation gates for high-stakes targets; see recommendations below. Optional `app` focus guard on `mac_paste` / `mac_key` (and `mac_type` keystrokes) refuses input unless that app — compared by process, not by name — is frontmost; `mac_type` keystrokes after a click on an `element_index` go out only if the element's app is then frontmost. An `element_index` is re-identified inside the window it came from (by CGWindowID) before any action, and a physical click or drag (both ends) is sent only when a hit test shows the point reaches the element, or — when the hit test is inconclusive — when the topmost on-screen window at the point is that same window (by CGWindowID, not covered by another window of the same app; `occluded` otherwise). Right before a physical click or drag is sent, the window on top at each point is checked again (by CGWindowID); afterwards a physical click counts as `delivered_verified` only if the element is still there, changed, and its own window is still on top at the click point. An element read with `surface: "app"` is bound to its window's CGWindowID, and an element in a window without a CGWindowID (other than Finder's desktop) is refused with `policy_denied`. A `mac_click` at raw x,y is sent only when the topmost on-screen window at the point belongs to `app` (default: the frontmost app; the menu bar counts as the frontmost app's, and the strip a display keeps for the Dock counts as the Dock's; Notification Center's full-display overlay counts only over a banner or alert it draws, or everywhere when their frames cannot be read), unless `force: true`; a short gap remains between that check and the click. `mac_key` refuses quit / log-out / lock / force-quit / delete-immediately / empty-Trash chords without `force`; `mac_menu_command` applies the same chord list, refuses Apple-menu items without `force`, and never quits the MCP host or a session process. |
| 3 | **Arbitrary JS in browser** | `browser_evaluate` executes any JavaScript in the page context | **Partially mitigated** | Off by default: `browser_evaluate` returns `eval_disabled` unless the server was started with `NORACU_ENABLE_EVAL=1`, and `NORACU_DISABLE_EVAL=1` keeps it off even then (it stays listed in `tools/list`). Once it is turned on, any script runs in the page |
| 4 | **Input validation gaps** | Malformed arguments (NaN coordinates, oversized strings, `javascript:` URLs) | **Mitigated** | `validateArgs` validates every tool's arguments (types, ranges, enums, string lengths, URL schemes) before any subprocess runs; `tools/list` emits `required` arrays derived from non-optional arguments |
| 5 | **Screenshot privacy** | `mac_screenshot` / `phone_screenshot` capture the full screen / phone display | **Inherent** | Run in a dedicated macOS user account or virtual display for untrusted automation. `NORACU_READ_ONLY=1` prevents side effects (and skips `enableWebAccessibility` on apps), not screen secrecy: `mac_screenshot` still shows visible notification banners on screen, and Notification Center accessibility reads via `mac_ax_state` / `mac_find` are not blocked by bundle id |
| 6 | **iPhone operations** | `phone_tap` / `phone_type` can interact with payment and SMS-verification UIs; taps go to OCR coordinates with no element re-check | **Inherent** | Keep Mirroring off for untrusted sessions; `NORACU_READ_ONLY=1` refuses all phone input; all phone input (including `phone_home` / `phone_app_switcher`, via `require_enabled` on the menu item or `imctl`'s `_require_live`) fails closed with `mirror_not_live` when not live — without stealing focus when paused or closed — or `mirror_state_unknown` when the state cannot be read, checks that iPhone Mirroring is frontmost before synthesized events, and never falls back to a second gesture after an uncertain menu timeout (`menu_unknown`); optional `expect` OCR anchor gates coordinate/key/type actions; "Authenticate automatically" lets anyone at the unlocked Mac start mirroring |
| 12 | **Phone screen as model input** | `phone_screenshot` / `phone_ocr` / `phone_find` — and, under the XCUITest backend, `ios_screenshot` / `ios_snapshot` — return notifications, messages, mail and one-time codes visible on the phone | **Inherent** | Use a Focus mode and a neutral app; the MCP client sends tool results to its model; iPhone notifications also reach the Mac once Mirroring is set up |
| 7 | **Supply chain** | malicious PRs / dependency poisoning after open-sourcing | **Partially mitigated** | Review all PRs touching `src/server.mjs` argument handling; lockfile committed; no `postinstall` scripts; the only runtime download is the one-time Playwright `chromium` install triggered by `browser_launch`, which can be disabled with `NORACU_DISABLE_AUTO_INSTALL=1` |
| 8 | **Local file read via browser** | `browser_navigate` to a `file://` URL, then `browser_read` exfiltrates local files; or a tab that someone opened on a local file becomes the active page | **Partially mitigated** | `file://` blocked at the `browser_navigate` argument and at the `url` of `browser_tabs` `new` unless `NORACU_ALLOW_FILE_URL=1` (initial URL only; redirects fall under threat 9). A tab becomes the active page — through `browser_tabs` `select`, or by taking over when the active tab closes — only when it shows an http(s) page, or is still on the blank page that `browser_launch` or `browser_tabs` opened it on (a blank page a tab shows after it has loaded anything else does not count: one reached from a local file still loads other local files into frames, where a screenshot shows them). The session's first tab is Chromium's own, so it is not taken on trust: when it starts on a blank page noracu sends it to `about:blank` itself, checks that a new document is there, and empties `window.name` before it counts (measured: after that navigation a blank page that a local file went to no longer loads local files and the old document is gone; the name survives it), and any navigation the tab reports afterwards ends that — also one back to an earlier blank page in its history (measured: `history.back()` to a blank page that a local file had reached loads local files again). A first tab that starts on anything else is held to the rule like any other tab. A tab restored at launch was looked for and not seen: a headed Chromium started the way noracu starts it, on a profile set to continue where it left off whose last session had a blank tab that a local file had gone to, came back with one fresh blank tab (two runs); the checks above do not rely on that. The tab that already is the active page is held to the same rule each time a page tool is called: once it shows anything else — a blob the page made, Chromium's page for a load that failed, a blank page after another page, a local file someone opened in that tab — the page tools return `active_page_not_allowed`, and only `browser_navigate` (which reads nothing of the page it leaves) and `browser_tabs` act. A tab on a local file, a browser page or a blob, and a blank tab that a page opened (it shares that page's origin and can read it), are listed with their url and title and nothing else of them is read: `tab_not_selectable`, and `no_active_page` from the page tools when no other tab is open. What a tab shows is looked at when a call starts, by the address the browser reports for it then; while a navigation is being committed that is still the old address for a moment (measured after a load that failed: calls sent with no pause got past this check every time). So the tools that return page content — `browser_read`, `browser_snapshot`, `browser_screenshot`, `browser_evaluate` — look again once they have their result, or an error, and drop it when the page no longer passes — or when the tab went through a page that does not pass while they worked and is back on one that does (measured: 60 calls in that moment, none handed over the arriving page; this rests on the browser reporting a navigation before it answers from the new page). The input tools are checked at the start only: in that moment input can reach the page that is arriving. A page cannot take itself to a local file or a browser page (Chromium refuses that), and the browser tools' own keystrokes go to the page, never to the address bar (measured in a headed Chromium), so the arriving page is a local file only when one is opened in the active tab from outside the browser tools — by hand, or by Mac-layer input. Remaining: input that reaches an arriving page in that moment (a click or fill by selector also tells whether the selector exists there). Outside this row: a session attached to an app with `cdp_port` (threat 15), which uses that app's own pages whatever they show; and the Mac layer when it is on — its input can type an address into a headed browser's address bar, and `mac_screenshot` shows the browser's window like any other (threats 2 and 5) |
| 9 | **HTTP GET side effects** | navigation triggers logout links, one-time tokens, private-network / cloud-metadata endpoints | **Not mitigated** | No URL blocklist (redirects and DNS rebinding defeat pre-navigation checks); client-side policy |
| 10 | **Clipboard clobbering by mac_paste** | `mac_paste` overwrites the clipboard with the pasted text | **Partially mitigated** | One engine call copies every clipboard item and type aside (inside that process), writes the text marked `org.nspasteboard.TransientType`, sends ⌘V only if the clipboard and the frontmost app are unchanged, and puts the user's items back after the paste shows in the same focused element (held at least 0.3 s; else after a 1 s hold) and only if nothing else wrote to the clipboard meanwhile; when the keystroke may not have completed it is not put back. An item marked concealed (on any clipboard item) is never copied: the clipboard is cleared after the paste. Universal Clipboard content and clipboards over 64 MB are refused unless `force`. Remaining: for up to about a second the clipboard holds the pasted text (a clipboard manager that ignores the transient marker can record it); an app that reads the clipboard after the hold receives the restored content; when the app stops answering the pasted text is left on the clipboard |
| 13 | **Actions on windows the user cannot see** | Semantic Mac actions (press, set value, insert text) work on background windows without moving the pointer or taking focus | **Inherent** | Results report `delivery` and `retry`; review the client's tool log; close high-stakes apps during unattended runs |

## Hardening recommendations

- Leave `NORACU_ENABLE_EVAL` unset unless you actively need `browser_evaluate`; `NORACU_DISABLE_EVAL=1` keeps it off whatever else is set.
- Set `NORACU_STOP_FILE` to a path you can `touch` in one step (a shell alias, a Shortcut) so you can stop all Mac and iPhone input, and the browser tools that act on a page, at once (`browser_launch` and the reading tools are not stopped); delete the file to resume.
- For unattended runs, set `NORACU_APPROVAL_FILE` and list only the apps the task needs under `allow`.
- Leave `NORACU_ALLOW_CDP` unset unless you drive an Electron app's web contents; quit the app when done so its DevTools port closes.
- `NORACU_TRACE` writes only `{ ts, tool, args, ms, error, code }` — argument names and sizes, error code prefix, never argument text, result text, or error messages — and opens the file `0600` with `O_NOFOLLOW` (refusing symlinks).
- Before an agent touches the iPhone layer: turn on a Focus, open a neutral app,
  and start with `NORACU_READ_ONLY=1`. Prefer "Ask every time" in iPhone
  Mirroring settings unless you need unattended sessions.
- Gate `mac_type` / `mac_paste` behind human confirmation when the frontmost
  app is a password manager or banking site (client-side policy).
- Run untrusted automation in a dedicated macOS user account with
  Accessibility + Screen Recording granted only to that account's client.
- Audit tool calls in your MCP client's log — every action is visible there.
- The persistent browser profile at `~/.noracu/browser-profile` keeps cookies
  across sessions — clear it between untrusted runs.
- `NORACU_READ_ONLY=1` does not block the one-time `playwright install
  chromium` download triggered by `browser_launch`; set
  `NORACU_DISABLE_AUTO_INSTALL=1` to require a manual install instead.

## Reporting a vulnerability

Please report security issues privately through a GitHub Security Advisory
(repo → **Security** → **Advisories** → **Report a vulnerability**). Do not
open public issues for exploitable bugs. We aim to respond within 72 hours.
